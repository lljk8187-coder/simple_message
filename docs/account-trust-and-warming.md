## 一、影子限流：一条消息的生命旅程

消息发出后走 4 站，**前三站全绿，死在第四站，且客户端零感知**：

```
发送(带签名) → 网关验签 → ACK 回执("收到了") → 投递 pipeline 风控审判
                                                   └─ 余额不足 → 静默丢弃
```

- ACK 只代表验签通过、身份合法；**投递决策在下游反垃圾系统异步做出**
- 客户端无错误码、无通知——只能靠 12.5s 回读验证（`send_to_peer._landed`）探测
- HTTP 兜底通道汇入同一 pipeline，同样被吞
- 静默是刻意设计：拒绝不带原因，对抗者无法二分定位触发条件

## 二、核心模型：设备信用存折

服务端为每个 `ttwid`（设备标识，形如 `1|指纹|时间戳|签名`）维护一本**使用信誉账本**。发陌生人消息（冷建联）是最高危操作，直接查余额。

**10-30 对照实验（决定性证据）**：

| 变量 | obb815（对照） | gb_innerchild（实验） |
|---|---|---|
| ttwid 年龄 | 33 天持续使用 | 当天新签 |
| 出口 IP | Vortex（相同） | Vortex（相同） |
| 签名档位 | tier B | tier B（当天刚升） |
| 文案 | 同一条 | 同一条 |
| 冷发结果 | **sent 落地** | **ACK ok but dropped ×3** |

此前 7 组排除实验已逐一否决：msToken 缺失、cookie 转义损坏、ttwid-账号硬绑定、UA 绑定、Cookie/URL 一致性、游客自签 ttwid（同出口现签也 400）。

**结论：主导变量 = 身份要素（ttwid + sessionid + ticket guard）的使用历史长度。**
时间与行为数据只能真实流逝，无法伪造——这就是"没有破解级解"的根本原因。

### 附：ttwid 握手校验的观察（逆向侧）

- IM WS 握手（im-ws.tiktok.com/ws/v2）的 URL 参数 `ttwid` 是唯一敏感变量
- 服务端不校验 ttwid 与账号的绑定（jakson 的 ttwid + gb 的 sessionid 也 101）
- 零历史 ttwid（游客流程、外部浏览器签发）一律 400 且响应体为空
- ttwid.tiktok.com 签发接口从当前出口不可达（000），www 首页可自然签发但同样无信誉

## 三、账号状态机

```
trusted ──冷发预算耗尽──> shadow(影子限流) ──持续高危──> restricted ──> banned
   ▲                        │
   └────── 滚动窗口回血(~18h 实测) ──────┘
```

- **shadow 是可逆中间态**：jakson 实测恢复 ≤18.2h，是"预算花完"不是"拉黑"
- **冷发预算 ≈ 30 条/24h/号**（滚动窗口），内容因素已排除（A/B 12/13 落地）
- **新号 = 零余额冷启动**：任何单次冷发都在阈值之下，全吞

## 四、环境隔离规范（防连坐）

服务端维护账号↔设备关联图，共享环境 = 图上画边 = 多号连坐。

| 层 | 规范 | 状态 |
|---|---|---|
| 浏览器 profile | **一号一档**：受控登录弹窗填的账号名即 profile 键（`login-profile/tiktok-<名>`），重登同号复用同档 | ✅ 已实现（2026-10-30） |
| 设备指纹 | ttwid 指纹段一号一套，**永不交叉**（借 ttwid 给别的号 = 图上画强关联边） | 运营纪律 |
| 出口 IP | 一号一"固定出口"；2-3 号共享一个出口可接受（家庭 WiFi 类比，弱信号）；8+ 号再分 IP | 当前 3 号 1 出口，安全 |
| IP 稳定性 | 号与出口的绑定关系要恒定；漂移（A 网登录 B 网使用）对低龄号重罚（gb 10-30 实证） | 运营纪律 |

## 五、养号 SOP（新号上产流水线）

1. **手机端预养 1-2 天**：手机设备注册是硬件级（GAID 等），一份手机历史比几天网页浏览"重"
2. **受控浏览器登录**（hub 前端 → 添加账号 → 浏览器登录，填账号名）——凭据从 hub 出口签发，ttwid 天然合法；自动收割 ticket+私钥升 tier B
3. **D0：只养不发**——刷 FYP、看主页，产生"正常人类"行为记录
4. **D1：单发试水**——给 1 个陌生人发 1 条，回读判落地
5. **D2+：小步放量**——落地正常再 2 → 5 → 10；任何一次不落地立即回退
6. **禁区**：新号首日冷发营销话术 = 最差画像；failed 目标勿反复重发

## 六、Camoufox 路线（矩阵扩大后的设备层升级）

现状：playwright 受控 Chromium 的 canvas/webgl 指纹是本机固定的，一号一 profile 只隔离了 Cookie 层，**设备指纹层仍是同一台机器**。Camoufox（基于 Firefox 的反检测浏览器，本机工具链已装）可给每号注入独立且自洽的指纹。

**启用条件**：号数 > 5 或出现关联连坐迹象时。

**四条使用纪律**：

1. **指纹持久固化**——每号一套 config 存盘，绝不每次随机（随机 = 每次换设备，比不隔离更糟）
2. **指纹与出口 IP 对齐**——时区/语言/地区跟 IP 地理一致（US IP → `America/New_York` + en-US），不一致是最经典翻车点
3. **IP 密度克制**——一出口 ≤ 3-5 号；扩矩阵时上静态住宅代理（机房 IP 基础分打折）
4. **行为层勿机器化**——匀速滚动/恒定停留比指纹更容易暴露；真人操作最优，脚本需足量随机化
